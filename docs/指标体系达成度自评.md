# 对照《NovaPilot 量化指标体系 v1.1》的达成度自评

> 评估日期 2026-09-06。被评对象:本仓库 v3.2.1 工作树(363 单测 / 27 文件全绿,`tsc --noEmit` 干净)。
> 评估方式:逐条核对指标体系文档的每个指标**是否有真实数据源 + 聚合 + 成对护栏**,
> 而不是「是否在文档里被提到」。判定分三档:**已落地** / **部分**(有原始数据但无聚合,或用代理口径) / **未落地**。

## A. 埋点缺口闭合(24 / 25)

文档第 12 节自述「缺口四处」,并给了落地顺序
**A(生命线)→ D(改动小见效快)→ B/C → 看板按第 10 节重组**。按此顺序全部完成。

| 编号 | 文档要求 | 实现 | 判定 |
|---|---|---|---|
| A | 出卡前对引用号做反查审计,「离线复用 NovaGuard 反扫逻辑」 | `auditCitations()` 纯函数、无 IO、离线可复现;持久化 `recordCitationAudit()` 分离 → `citation_audits` | ✅ |
| D | 决策卡复制 / 导出 / 同步事件 | `adoption_events` + `/api/adoption`;`copy` / `export` 已接 | ⚠️ 见下 |
| B | 复核队列加「应放/应拦」字段 **+ judge 预审管线** | `review_samples` + 两级判定(`setJudgeVerdict` / `setExpertVerdict`)+ `npm run review:judge` | ✅ |
| C | 专家办结「是否产出候选知识」标记 | `case_closures`;缺理由时**抛错**而非吞异常 | ✅ |

**扣 1 分**:埋点 D 的三个采纳通道里 `sync`(同步至多维表格)**没有 UI 触发点**。
这是有意的 —— 飞书多维表双写(`graph.ts:421`)是每张卡自动执行的,不是用户动作,
计入采纳事件会把采纳率推到 ~100%,正是第 4.4 节点名的游戏化失败模式。理由成立,
但严格按文档列出的三个通道口径算,缺一个。

**超出文档要求的一处**:新增 `latency_samples`。第 10 节要求 P95 延迟必须与防线结构
成对看,而改造前系统里一个延迟数都没落库 —— 这一格若留空,那一行护栏对就只是排版。

## B. 护栏对成对上板(15 / 20)

**结构层面满分**:`guardrailBoard(db, sinceIso)` 一次算完六对、**同源同窗**;
`PairRow` 类型强制 `guardrail` 与 `guardrailValue` 必填,所以这张板**在类型层面放不下
一个孤零零的激励指标**;所有率在无样本时是 `null` 并渲染成 `—`,不充 0。

## E. 口径纪律与反游戏化(12 / 15)

第 13 节列了 8 条「本体系最可能出错的地方」。逐条核对:

| # | 反思项 | 是否守住 |
|---|---|---|
| 1 | 「未转专家」边界需拍板,口径变了整棵树分母都变 | ✅ 按文档建议口径实现:转接会话**进分母不进分子**;分母按 `trace_id` 去重(`decision_cards` 主键是 `(id, version)`,拿行数当分母会让一个反复改事实的用户把解决率冲低) |
| 2 | 建议目标全是「估」,不作承诺 | ✅ 只硬编 `P1_THRESHOLDS` 三条(均来自文档第 11 节),其余不设阈值 |
| 3 | 前 4 周只看趋势不看绝对值 | ✅ `pendingReviewLoad` 单独一格,提示「这些率还不可信」而不是报警 |
| 4 | judge 兜底本身也可能失效(专家样本太小时一致率不可信) | ✅ 一致率为 `null` 时不报警、渲染 `—` |
| 5 | **漏放率分母是金标幻觉库,库太小则「漏放率 0」是假安全** | ❌ **没守住** —— 幻觉子集未建,而看板显示漏放 0。这正是文档警告的那种假安全 |
| 6 | Hit Rate@5 在 7~15 篇库上偏高,不能外推 | ○ 指标未落地,B2 文档已写明「留作扩充语料后复核」 |
| 7 | 隐式采纳率需在看板注明口径 | ✅ 看板脚注打印第 4.4 节边界:采纳率**不进可信解决率计算链** |
| 8 | 演示就绪度分支工业化后整支移除 | ○ 仍在比赛期,不该移除 |

**加分项**(文档没要求但属于同一纪律):

- 拒绝把 `retrieval.ts` 的 `elapsedMs` 标成端到端 P95 —— 那是偷换口径,而这张看板存在的意义就是防这件事;
- 延迟样本带 `card_status`:状态盲的全局 P95 分不出「真的变快了」和「把该升级的问题硬答了」;
- 抽样一律用 traceId 的 FNV-1a 哈希,**不用 `Math.random`**,保证离线可复现;
- 修掉一个自己制造的静默归零 bug:`knowledgeVolume` 查了不存在的 `documents.created_at`,被兜底 `try/catch` 吞成「这一格是 0」——0 在看板上和真实的 0 长得一模一样。对策是 `console.error` 带 `口径缺格` 标记 + 每个子查询都有断言 **> 0** 的单测(只断言 0 的测试对这类错误完全免疫)。

## 下一步最高杠杆的三件事

按「补一项能点亮多少格」排序,不按工时:

1. **建一张检索日志表**(查询、通道、`fallbackReason`、候选与分值、过阈判定)。
   一次点亮 **4 项**:短查询回退触发率、SOP 覆盖率、知识盲区主题数、单篇知识健康度,
   并让第 11 节的 **P2 告警路径**从「无数据源」变成可用。现在这些数据虽在
   `checkpoints.state` 的 JSON 里,但主键 `(trace_id, node)` 会让三轮检索互相覆盖 ——
   不能靠聚合 checkpoints 绕过。

2. **给 NovaBench 加幻觉样例子集**。这是唯一一条**文档已预警、而我们正踩在上面**的假安全
   (E-5)。补上之后「漏放率」才从代理口径变成真口径,「可信解决率 ↔ 漏放率」这一对
   才算真的成对。

3. **`expert_cases` 补 `resolvedAt` + `candidates` 补 `published_at`**。两个列,点亮
   专家 SLA 达标率(4h 实质响应)与候选→全量周期 —— 这两项目前是**结构性**不可算,
   不是缺聚合。

引用核实合规率(PMID/DOI 外部核实)刻意排在三项之后:它需要联网核实,与
「离线运行是硬不变式」冲突,应设计成**入库前的离线校验步骤 + provenance 留痕**,
而不是运行时查询 —— 这是一次口径设计,不是一次接线。
