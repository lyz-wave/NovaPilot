# NovaPilot × 飞书五合一集成说明

五个飞书能力全部接入,统一原则:**凭证缺失时全部优雅禁用**——不配置任何飞书凭证,
系统保持离线确定性运行,任何功能不受影响;配置后逐步启用。

## 一、五个能力各自怎么用

| 飞书能力 | NovaPilot 落点 | 实现文件 | 需要你在飞书侧做什么 |
| --- | --- | --- | --- |
| **企业豆包** | LLM 推理后端(火山方舟 OpenAI 兼容协议) | src/server/feishu/doubao.ts + 既有模型网关 | 在火山方舟开通豆包模型,拿 API Key 填 FEISHU_DOUBAO_API_KEY |
| **aily 智能助手** | 客服入口:aily 技能调用 /api/feishu/aily-webhook,决策卡以消息卡片回传 | src/server/feishu/aily.ts + api/feishu/aily-webhook | 在 aily 中创建技能,配置 HTTP 请求指向本服务 webhook |
| **多维表格** | 系统数据双写:决策卡、质量事件自动同步到 Bitable | src/server/feishu/bitable.ts(决策卡在生成时、质量事件在 open/resolve 时自动写入) | 建一个多维表格,把 app_token 填 FEISHU_BITABLE_APP_TOKEN(表由系统自动创建) |
| **妙搭** | 无代码看板:基于上面两张 Bitable 表拖出运营看板(妙搭无对外 API,交付表结构+视图配方) | 见 docs/feishu/妙搭看板表结构.md | 在妙搭中按配方搭建视图(10 分钟内) |
| **智能纪要** | 会议纪要→咨询入口:拉取妙记文本→抽取 DV200/样本数/物种等项目事实 | src/server/feishu/minutes.ts + api/feishu/minutes-import | 给应用开「妙记」权限,并把它加进需要读取的会议 |

## 二、配置步骤(飞书侧,一次性)

1. 打开 open.feishu.cn 开发者后台 → 创建企业自建应用,拿到 App ID / App Secret。
2. 权限管理里为应用开通:多维表格(bitable:app)、妙记(minutes:minutes 读取)。
3. 管理员在「应用发布」里发布(或加入测试租户),应用对你企业可见。
4. 把凭证填进项目 .env(参考 .env.example):

    FEISHU_APP_ID=cli_xxx
    FEISHU_APP_SECRET=xxx
    FEISHU_BITABLE_APP_TOKEN=bascnxxx
    FEISHU_DOUBAO_API_KEY=xxx
    FEISHU_DOUBAO_MODEL=doubao-1-5-pro-32k-250115

5. 重启服务即生效;运营页运行 NovaBench 时豆包 profile 自动注册并激活。

## 三、API 速查

- POST /api/feishu/minutes-import { minuteToken } → { minutes, facts }
- POST /api/feishu/aily-webhook { question, facts?, locale? } → { reply, status, card(飞书消息卡片), decisionCardId }

aily 技能请求示例:

    { "question": "24 份 FFPE 样本 DV200 37% 如何做转录组分析", "locale": "zh" }

## 四、验证方式

- 无凭证(默认):npm test 全部离线单测(含 feishu.test.ts)必须全绿。
- 有凭证:生成一张决策卡 → 多维表格「决策卡」表出现该记录(幂等 upsert);运营页注入退化→事件表出现 OPEN 记录→关闭后变「已关闭」。
- 妙记:把应用加入会议 → 调 minutes-import 传入 minute_token,返回事实抽取结果。
- aily:aily 技能配置 webhook → 问科研问题 → 收到决策卡消息卡片。

## 五、注意

- 飞书调用全部 fire-and-forget + 失败静默,绝不阻塞主流程、绝不破坏离线不变式。
- 妙搭/企业豆包(飞书内产品界面)没有对外 API,以上是它们各自最合理的接入方式。
